大模型的训练数据，是怎么生产和质检的

李璐 Giraffe · 约 6 分钟读完
——想象这是一家给大模型"做饭"的中央厨房，我们要把各种 raw 食材（互联网上的乱七八糟的数据）加工成模型能吃的"营养餐"。

🍳 整体比喻：大模型的中央厨房

大模型训练就像喂一个超级巨婴吃饭。Pretrain/Midtrain 数据流程，就是从菜市场买菜 → 洗菜切菜 → 质检挑虫 → 营养配比 → 端上桌的全过程。

1️⃣ 数据引入 = 去菜市场进货

开源数据集 / 网页 / 书籍 抓取与管理

这就是采购员去各种地方进货：

去开源菜市场（开源数据集）批发成箱的食材

去互联网大集（网页）随手抓一把

去书店（书籍）整本整本地搬

这整个厨房，是专门给"中训练"（Midtraining）阶段备菜的。

2️⃣ 数据解析 = 拆包装

json/txt 解析、html 解析、epub、PDF 解析

买回来的食材包装各异：

有的装在纸箱（json/txt）

有的装在塑料袋（html 网页）

有的装在铁罐头（PDF、epub 电子书）

这一步就是拆包装，把里面的"肉"（纯文本内容）取出来。虚线框表示 epub/PDF 不好拆，可能要特殊工具。

3️⃣ 数据接入 = 入库登记 + 初步筛选

MD5 去重、格式校验、路径校验、fasttext 语种划分、后训练通用质检、平台建卡

拆完包装后，先别急着做菜，得在仓库门口过一遍：

操作 通俗解释
MD5 去重 这箱菜是不是刚才已经搬过一箱了？一模一样的不要重复搬
格式合规校验 检查包装有没有破损、是不是我们要的规格
存储路径校验 仓库货架号对不对，别放错地方以后找不到
fasttext 语种划分 这是中文白菜还是英文萝卜？分门别类放
后训练通用质检 用自动化仪器快速扫一遍，明显烂掉的先扔掉
平台建卡 给每批货建个档案卡，记录从哪来、什么品质

4️⃣ 模态加工 = 深加工 / 翻译

ASR（语种选择）、人工质检、后训练人工质检

有些食材不是现成的文字，需要加工：

ASR：把语音（比如视频字幕、播客）转成文字，相当于"听写翻译"

人工质检：老师傅肉眼检查，要求合格率 > 90%（比如看 PDF 解析出来的文字有没有乱码、缺页）

后训练人工质检：专门针对"后训练"（SFT/RLHF）阶段的数据，要求更细

这里有个硬指标："文档解析页数合格率 90% 以上"——意思是拆 PDF 不能拆一半漏一半，100 页的书至少得正确拆出 90 页。

5️⃣ 质量监控 = 质检流水线（核心关卡）

乱码检测、低质多维度、去重、子句去重、试题质量、后训练质检算子、specialtoken 替换

这是整个厨房最忙的质检车间，一道道关卡过筛子：

关卡 通俗解释
乱码检测（必检） 这盘菜里有没有沙子？（比如 \x00\x01 乱码字符）——必检项，一个都不能漏
低质多维度 从多个角度评判：是不是太短？是不是无意义重复？是不是广告垃圾？
源内/全局签名去重 这批菜和仓库里已有的菜是不是重复？先查自家仓库（源内），再查全国仓库（全局）
子句去重 就算整篇文章不一样，但里面某句话反复出现（比如"点击关注不迷路"），也要把重复的句子删掉
试题质量 如果是考试题/题库数据，专门检查题目质量
后训练质检算子 专门给后训练阶段数据用的特殊检测工具
specialtoken 替换 把食材里的"特殊标记"统一换成标准标签。比如把各种奇怪的换行符、分隔符统一格式
小字提示："高质量数据可跳过全环节"——意思是免检产品（已经知道很干净的数据）可以走绿色通道，不用排队过每一道安检。

6️⃣ 准出检测 = 出厂前的最终抽检

人工算子阈值、自定义规则过滤、人工随机抽样质检

要出厂了，最后一道门：

人工算子阈值：设定一个分数线，比如"纯度必须达到 95 分才能出厂"

自定义规则过滤：客户有特殊要求？比如"不要带特殊 token 的数据"，在这里统一过滤掉，顺便合并相同的 special token

人工随机抽样质检：随机抽几箱打开看看，人工确认没问题才盖章放行

7️⃣ 数据分析 = 给这批货做体检报告

语料查询、数据集查询、数据画像、覆盖分析（benchmark 反查）

货已经合格了，但还得分析一下这批食材的营养构成：

语料查询 / 数据集查询：这批货里具体有什么？有多少中文、多少英文、多少代码？

数据画像：用数据画像工具给这批数据"画个像"——像不像优质数据？分布均不均衡？

覆盖分析（benchmark 反查）：用基准测试题倒查——这批数据能不能覆盖模型需要考的知识点？有没有盲区？

8️⃣ 数据交付 = 打包发货

数据集拆分合并、Part 均衡、数据压缩、存储路径生成

分析完了，按订单要求打包：

拆分合并：客户要 1000 箱，每箱 100 斤，重新分装

Part 均衡：各种食材配比要均衡，不能全是白菜没有萝卜

数据压缩：抽真空压缩，省运输空间

存储路径生成：生成"快递单号"（数据在分布式存储上的路径），告诉训练平台"货放在哪个货架"

9️⃣ 上车 & 训练 = 端上桌，开吃！

H5 制作、数据发版、数据配比（上车平台）、Benchmark 监控、下游反馈

终于到餐桌了：

H5 制作：做个漂亮的"菜单页面"（数据看板），展示这批数据的情况

数据发版：正式发布，像软件发版一样打上版本号（v1.0、v2.0）

数据配比（上车平台）：按菜谱比例下锅——多少中文、多少代码、多少领域数据，调比例

Benchmark 监控：模型吃完后考试，看看成绩有没有提高

下游反馈：如果模型考砸了（下游任务表现不好），反馈回最左边的"数据引入"，重新进货、重新洗——这就是"发现问题，持续优化"的闭环

🔝 顶部的"人工 + 自动化质检"

这条橙色横线贯穿了从数据解析到准出检测的整个过程，意思是：

全程都有机器人安检（自动化）+ 老师傅抽查（人工），双保险。

🔄 底部的"发现问题，持续优化"

这是一条反馈循环：

模型训练效果差
↓
下游反馈：这顿饭吃完拉肚子了
↓
回到源头：是不是菜没洗干净？是不是进了坏食材？
↓
从源头重新走一遍流程，优化改进

🎯 一句话总结

整个流程讲的是大模型中训练数据的"中央厨房"全流程：

买菜（引入）→ 拆包装（解析）→ 入库安检（接入）→ 深加工（模态加工）→ 多道质检（质量监控）→ 出厂抽检（准出）→ 营养分析（数据分析）→ 打包发货（交付）→ 端上桌给模型吃（训练）→ 吃坏了反馈回来重做（持续优化）

整个过程的核心就两个字："干净" + "均衡"——既要洗掉垃圾数据，又要保证各种营养配比合理，最后还要根据"食客"（模型）的反应不断调整菜谱。
